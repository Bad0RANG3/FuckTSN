# 字段对照：旧版 v2.0.23 → 新版 v3.6.814

> 本文件由 `tsn_fields.py` 渲染（`python tools/render_field_doc.py`），不要手改。
> 证据口径：`echo`=服务器回显原文，`probe`=我们自己发请求的返回，`doc`=APK 逆向笔记。

## 零、必须替换的字段（先改这张表）

共 26 个。权重「硬」= 不改直接判不合格/被拦/403；「软」= 改了才不留画像痕迹（证据多为相关性）。

| 字段 | 旧 → 新 | 权重 | 迁移动作 |
| --- | --- | --- | --- |
| `appVersion` | "2.0.23" → "3.6.814" | 软判定/风控 | 换成新版本号，并让 body/header/画像三处版本一致 |
| `identify` | "1" → UUID（大写小写都出现过；由 getExerciseStartTime 下发或本地生成） | 硬判定 | 必须是 UUID；它把人脸/轨迹/记录串在一起 |

| `sportRange` | "2.000"（公里，刚好等于下限） → "2.12"（公里，> rangeSetting 2.000，留 6% 余量；合格样本 2.010–2.140，回显成 3 位小数） | 硬判定 | 按真实距离保留 2 位小数，且必须 > rangeSetting（留 5% 以上余量） |

| `startTime` | 毫秒时间戳字符串 → 毫秒时间戳字符串，与 endTime 同一天 | 硬判定 | 按目标日生成，不要跨天；时段建议 06:00–21:00（实测最晚 21:10 开始也合格） |
| `brand` | "Xiaomi" → "iPhone" | 软判定/风控 | 换成 iPhone；服务器把它原样写进记录 |
| `model` | "Xiaomi 手机" → "iPhone 17 Pro" | 软判定/风控 | 同上 |
| `system` | "Android" → "iOS" | 软判定/风控 | 同上 |
| `version` | "14"（Android 版本号） → "27.0.1"（iOS 版本号） | 软判定/风控 | 同上；合格记录里 27.0.1 与 27.3 都出现过，属同一 iOS 大版本 |

| `s` | 瞬时速度（单位混乱） → m/s 字符串，6 位小数，中位数 1.2–3.6 | 硬判定 | 按分段距离/时长算，保留 6 位 |

| `e` | 缺失或为 0 → 累计步数，字符串；末点必须等于 step | 硬判定 | 单调累计，允许平台期；末点 == step |
| `i` | 缺失 → "true"/"false" 字符串；最后一点必须 "true" | 硬判定 | 暂停标记：静止段 true，末点 true |
| `m` | 缺失（旧脚本漏了这个键） → "0" | 无影响 | 写 "0" |
