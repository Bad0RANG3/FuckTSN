# 接口报文与判定说明

本文档回答一个问题：**同一份报文在不同地方曾经得出不同结论**（`code == 0` / `returnCode == '200'` /
`resp.json()` / `status_code == 200`），现在统一由 `tsn.protocol.classify_response()` 判定。
下文列出三类传输通道、全部接口、真实见过的报文，以及每类报文对应的动作。

```
TiShiNengSdk*.py  ──> tsn.http.TsnHttpCore ──> httpx ──> 服务端
        │                    │
        │                    ├─ 传输层失败 → resilient_client 重试（连接/超时类）
        │                    └─ 收到响应 → classify_response() → TsnResult
        │                                          │
        └── raise_for_error()/to_error() <──────────┘
                                                   ├─ retryable? → 协议级重试（降级类）
                                                   └─ is_auth_expired? → 续期/重登
```

## 1. 传输通道

| 通道 | 方法 / 端点 | 参数位置 | 鉴权 | 备注 |
| --- | --- | --- | --- | --- |
| OAuth 令牌 | `POST auth/oauth/token` | **query string** | `Authorization: Basic base64(schoolCode:pig)` | 密码需先 AES 加密成块对齐密文；表单体会被拒 |
| 业务接口（公有版 `sysType=2`） | `GET`/`POST` 相对路径 | 加密后 `key`/`param` | `token` 头 + 签名 `v`/`appId`/`appSecret` | 加密参数较长，POST 表单常被 WAF 403，优先 GET |
| 业务接口（私有版 `sysType=1`） | `POST` 相对路径 | 表单 | `token` 头 + `appId`/`sign` | 人脸接口沿用 multipart 元组格式 |

URL 一律 `tsn.routes.join_url(base, path)`：`base.rstrip('/') + '/' + path.lstrip('/')`。
历史 bug 是 `base.rstrip('/') + path`，得到 `http://hostupms/...`。

## 2. 总判定表

判定顺序：**HTTP 语义优先，其次业务字段**。

| kind | 判定依据 | 典型报文 | 处理动作 | 重试 | 错误码 |
| --- | --- | --- | --- | --- | --- |
| `OK` | HTTP 2xx；`code`/`returnCode` ∈ {0,200}；或含 `access_token`；或顶层是数组 | `{"code":0,"data":{...}}` | 取 `data` 返回 | 否 | — |
| `BIZ_ERROR` | 有 `code` 但非 0/200，且无风控/降级特征 | `{"code":1,"msg":"密码错误"}` | 展示服务端 `msg` | 否 | 透传服务端码 |
| `AUTH_EXPIRED` | HTTP 401 | `{"code":401,"msg":"登录已过期"}` | 续期，失败重登后重放一次 | 否 | 401 |
| `ANTI_CHEAT` | HTTP **999**，或 `msg` 含 `禁跑黑名单`/`作弊`/`反作弊` | 见 §4 样本 1 | 立即终止，原样展示 | **否** | 999 |
| `RATE_LIMITED` | HTTP 428 / 429 | `{"code":1,"msg":"验证码不能为空"}` | 提示稍后再试 | 否 | 428 |
| `GATEWAY_BLOCKED` | 响应不是 JSON（HTML/空体/纯文本），或 JSON 解析失败 | 见 §4 样本 3、6 | 换传输方式或稍后重试 | 否 | 10002 |
| `SERVER_DEGRADED` | HTTP ≥ 500，或 `msg` 含 `server_error`/`internal server error`/`系统繁忙` | 见 §4 样本 2 | 退避重试 | **是** | 503 |
| `TRANSPORT` | 无响应 / 连接重置 / 各类超时 / DNS 失败 | `RemoteProtocolError` | 退避重试 | **是** | 10004 |
| `MALFORMED` | JSON 合法但既无 `code` 也无 `data`/`access_token` 的结构 | `{"foo":1}` | 记录报文，按契约变更处理 | 否 | 10002 |

业务字段取值优先级：`msg` → `message` → `returnMsg` → `error_description` → `error` → `statusMsg`；
成功时的数据取 `data`，没有 `data` 就返回整个 payload。

## 4. 真实报文样本与判断

**样本 1 — 反作弊（HTTP 999）**

```
HTTP/1.1 999
{"msg":"系统检测到您有作弊嫌疑已被拉入禁跑黑名单。请规范跑步行为，如有疑问请联系学校管理员","code":999}
```

判断：`ANTI_CHEAT`。属学校风控，任何重试都会加重标记；`TsnRunServer.startRun()` 在第一步
`getExerciseSetting` 即终止。

**样本 2 — 服务端降级**

```
HTTP/1.1 200
{"code":1,"msg":"Internal Server Error","data":"server_error"}
```

判断：`SERVER_DEGRADED`。实测该报文对**任意凭据**都返回（正确密码、错误密码、不存在的用户），
所以它不能解释为「密码错误」。`sdk/client.py` 现在映射为 `TiShiNengError(..., 503)` 并重试。

**样本 3 — 网关 HTML**

```
HTTP/1.1 200
<!DOCTYPE html><html><head><title>502 Bad Gateway</title>...
```

判断：`GATEWAY_BLOCKED`。历史代码在 `Response` 对象上取 `resp['returnCode']` → `TypeError`；
PR #42 起统一走 `classify_response`。

**样本 4 — 密码长度未对齐**

```
HTTP/1.1 500
{"msg":"...IllegalBlockSizeException: data not block size aligned","code":1}
```

判断：`SERVER_DEGRADED`（HTTP 5xx）。真实含义是**本地密码没有加密成 16 字节块整数倍**，
属于调用方 bug，不是服务端抖动 —— 看到这条先查 `tsn.crypto.AESCrypto.encrypt(..., zero_padding=True)`。

**样本 5 — 缺参数**

```
{"code":1,"msg":"验证码不能为空"}
```

出现条件：缺 `type=app`，或把密码参数放到表单体。判断：`RATE_LIMITED`/`BIZ_ERROR`，
按「参数位置错误」处理，改回 query string。

**样本 6 — 连接被直接断开**

`httpx.RemoteProtocolError: Server disconnected without sending a response.`

常见于 URL 拼错（`hostupms`）、网关丢弃长 query、或服务端过载。判断：`TRANSPORT`，可重试；
若同一个 URL 每次都断，先打印最终 URL 自查拼接。

**样本 7 — 脏数据回读**

```
{"code":1,"msg":"...syntax error, expect [, actual {, pos 0, fieldName null"}
```

出现条件：`geofence` 传了对象 `{"isOpen":0}` 而服务端按多边形数组 `[[{lng,lat},...]]` 解析。
判断：`BIZ_ERROR`（服务端 fastjson 报错）。提交前校验字段形状，不要依赖服务端容错。

**样本 8 — 按天去重**

同一天重复调用 `addExerciseRecord` 返回同一个 `exerciseRecordId`，且 `listExerciseRecord` 里
可能查不到该 id。判断：不是失败，是服务端按天合并；核对列表而不是只信返回值。

**样本 9 — curl 看到乱码**

带 `Accept-Encoding: gzip` 却不用 `--compressed`，输出是二进制。判断：不是接口错误，
加 `--compressed` 或删掉该头即可。

## 5. 排查决策树

1. **有响应吗？** 没有 → `TRANSPORT`：查 DNS、代理、URL 拼接、服务端是否在维护。
2. **是 JSON 吗？** 不是 → 看 `snippet`：HTML 标题常直接写明 502/403/WAF。
3. **HTTP 状态码是 999/401/428/5xx 吗？** 按 §2 总表处理；999 一律不重试。
4. **有 `code` 字段吗？** 有且非 0 → 看 `msg` 是否含降级/风控关键词，否则按业务错误展示。
5. **`code=0` 但语义不对？** 检查返回形状约定（`addExerciseRecord` 需要 `return_meta=True` 拿 id）。
6. **同一请求时好时坏？** 服务端降级窗口，重试可穿过；把 `context` 带上接口名便于对日志。

## 6. 重试策略

| 层 | 负责 | 触发条件 | 默认次数 | 退避 |
| --- | --- | --- | --- | --- |
| 传输层 `resilient_client` | 连接/读写/超时/DNS | `TRANSIENT_NET_ERRORS` | `TSN_MAX_RETRIES=6` | `0.5·2^n` + 抖动，上限 8s |
| 协议层 `tsn.http` | `SERVER_DEGRADED` | `TsnResult.retryable` | `TSN_PROTOCOL_RETRIES=5` | `0.5·2^n`，上限 8s |
| 业务层 | 无 | 401 由 `sdk/client.py` 续期/重登一次 | 1 | — |

两层不叠加：传输层只处理「没拿到响应」，协议层只处理「拿到了但服务端说它不行」。

## 7. 环境变量

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `TSN_MAX_RETRIES` | 6 | 传输层重试次数 |
| `TSN_RETRY_BACKOFF` | 0.5 | 传输层退避基数（秒） |
| `TSN_NO_RESILIENT` | 空 | `1` 时改用原生 `httpx.AsyncClient` |
| `TSN_PROTOCOL_RETRIES` | 5 | 协议层（降级报文）重试次数 |
| `TSN_TZ` | `Asia/Shanghai` | 时间戳渲染时区；缺 tzdata 时退化为固定 +08:00 |
| `TSN_KEY_FILE` | `%LOCALAPPDATA%/tsn/secret.key` | 本地密码加密密钥 |
| `TSN_MAX_FACE_BYTES` | 10485760 | 人脸图片大小上限 |
| `TSN_FACE_TRUST_HOSTS` | 空 | 允许下载人脸的私网主机白名单 |
| `DATABASE_URL` | `sqlite+aiosqlite:///./tsn_data.db` | 数据库 |

## 8. 日志与脱敏

- token、学号不再以 INFO 打印；`tsn.protocol.redact()` 可用于兜底。
- 重试日志只记录 `scheme://host/path`，丢弃 query（query 里可能有加密后的密码）。
- 非 JSON 报文只截取前 200 字符进日志，避免整页 HTML 落盘。

## 9. 错误码

| 码 | 常量 | 含义 |
| --- | --- | --- |
| 401 | `AUTH_EXPIRED` | 登录态失效 |
| 428 | `RATE_LIMITED` | 限流/需验证码 |
| 503 | `SERVER_DEGRADED` | 服务端降级 |
| 999 | `ANTI_CHEAT` | 反作弊/禁跑 |
| 10000 | `UNKNOWN` | 未归类 |
| 10001 | `RELOGIN_FAILED` | 重新登录失败 |
| 10002 | `GATEWAY_BLOCKED` | 网关/WAF/报文结构不符 |
| 10003 | `RUN_TIME_CONFLICT` | 跑步时间冲突 |
| 10004 | `TRANSPORT` | 传输层失败 |
| 20001/20002/20003 | `FACE_*` | 人脸列表/缺失/下载失败 |
| 200000 | `RUN_UNAVAILABLE` | 无可用跑步路线 |
