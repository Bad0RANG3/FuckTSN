本文记录每一轮重构**做了什么、为什么这么做、哪些故意没做**。报文判定细节见
[接口报文与判定.md](接口报文与判定.md)，合格判定见[合格规格.md](合格规格.md)。

# 第一轮（v3）：统一报文判定

## 结论

最要命的问题不是「某个接口坏了」，而是**同一份报文在五个地方各判一次**：
`code == 0`、`returnCode == '200'`、`resp.json()`、`status_code == 200`、`'addExerciseRecord' in url`。
于是 HTML 网关页在 A 处抛 `TypeError`、在 B 处静默成功；`code=1,msg=server_error` 被当成密码错误；
HTTP 999（禁跑黑名单）被当成网络错误重试几十次。

现在只有一个判定点：`tsn_protocol.classify_response()`。

## 分层

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 传输 | `resilient_client` | 只重试「没拿到响应」：连接重置、读写超时、DNS |
| 协议 | `tsn_http.TsnHttpCore` | 组装 URL/头/参数，调用 `classify_response`，只重试 `SERVER_DEGRADED` |
| 判定 | `tsn_protocol` | 报文 → `ResultKind` + `TsnResult`（可重试？需重登？给什么错误码？） |
| SDK | `TiShiNengSdkBase/Public/Private` | 签名、加密、业务字段，统一 `raise_for_error()` |
| 编排 | `tsnClient` / `tsnRunServer` | token 生命周期、跑步流程 |

两层重试不叠加：传输层管「没响应」，协议层管「有响应但服务端说它不行」。

## 主要改动

1. **统一判定与异常**：`tsn_protocol` 的 `ResultKind`（ok / biz_error / auth_expired / anti_cheat /
   rate_limited / gateway_blocked / server_degraded / transport / malformed）、`TsnResult`；
   `TsnProtocolError` 带 `kind`/`http_status`/`server_code`/`snippet`/`context`；删掉吞错式
   `except Exception: return None`。
2. **令牌链路**：令牌端点固定 query string（表单体会被拒）；`getAccessToken`/`freshToken` 失败抛
   明确异常；过期判断用 `token_updated_at + expires_in - 120s`；私有版 `refresh_token` 的写死 `'2'` 改为空串。
3. **URL 与路由**：统一 `join_url`，修掉 `http://host` + `upms/...` → `http://hostupms/...`；
   `normalize_base_url` 不再把裸域名静默替换成默认网关；新增 AST 契约测试保证「代码引用的路由名」
   都在路由表里。
4. **本地安全**：密码与 token 走 `tsn_secrets`（AES-GCM，`enc:v1:`，密钥在
   `%LOCALAPPDATA%/tsn/secret.key`）；人脸走 `tsn_face_store`（路径白名单、magic 嗅探、私网拒绝、
   大小上限）；`main.py` 用 `getpass`；日志不打印 token/学号。
5. **明确性**：`httpPost(..., return_meta=True)` 取代按 URL 子串改返回形状；`isFaceStatus` 用配置值；
   时间戳统一按 `TSN_TZ` 渲染，缺 tzdata 退化为固定 +08:00。

## 故意没做

| 项 | 原因 |
| --- | --- |
| 拆 `TsnRunServer` 的传输/存储/图片职责 | CLI 直接 `new TsnRunServer(accountId=...)` 并写回属性，动构造签名会断链路 |
| 工厂不再写库（`getPublicVersionClient` 内部落 token） | `main.py` 依赖 `getTsnClientById(accountId, session)` 的副作用 |
| 三套签名合并 | 公有 RSA(appSign)+AES、私有 token 派生双签；签名字节错一次就全站 403，需 golden 报文才能动 |
| `gitudeLatitude` 等拼写错误改名 | 它是服务端接口字段名（`latitude` 少个 `t` 是服务端的历史拼写），改名即 403 |
| 学校后端只给 http 时强制 https | 公有版学校确实只给 http，改为启动提示而非强制 |

# 第二轮（v4）：从「能跑通」到「敢提交」

| 模块 | 职责 | 为什么单独存在 |
| --- | --- | --- |
| `compliance.py` | 成绩门禁，`error` 直接抛 `ComplianceError` 中止上传 | 判定必须在**发请求之前**跑完，不能等回包才发现不合格 |
| `track_shape.py` | 椭圆 / 折返 / 8 字三种跑道原型 + 车道漂移 | 只扰动同一条参考线时，14 条轨迹航向分布相似度 0.83，聚类一眼分组 |
| `backfill.py` | 批量补跑：台账、每日上限、时间窗、间隔、失败即停、盯守 | 「一次交 14 条」和「分 5 天交」在人工审计眼里完全不同 |
| `verify_plan.py` | 独立复核器：自己实现 haversine 与阈值，**不复用 compliance** | 同一个函数既生成又验证等于自己判卷；第二实现才抓得到「压线」 |

```
track_*  →  TiShiNengRunPathManage  →  compliance.check_submission  →  tsnRunServer 上传
（像人）        （App 原生字段格式）        （不过就不发）                （签名+加密）
                                          ↑
                                   verify_plan.py（独立复算）
```

### 门禁为什么分 error / warn

- `error` = 服务端历史上确实因此判过「不合格 / 作弊」的特征（人脸缺失、步数不足、点字段类型错、
  JSON 列畸形）。
- `warn` = 只是「不像真机」的统计特征。它们不该阻断提交，但会写进报告，方便事后复查。

> v5 起这套二分被 [四档分层](#第四轮v5分档门禁) 取代。

# 第三轮（v6）：全模块独立重写

## 为什么重写

判定层和服务层里有一批文件是**旧实现**（作者 `dispose0335/TiShiNengRunning` 的 MIT/GPL 代码），
与本仓库其余部分的风格、错误处理、日志、类型标注都不一致；其中若干模块的行为还**与逆向结论相反**
（例如把 `startQualifiedTimeSetting=6` 当成「早上 6 点」、要求点位时间戳整秒、
对 5 条真实合格记录会误杀）。与其在旧代码上打补丁，不如按我们的逆向事实重写一遍。

## 删了什么

| 删除 | 原因 |
| --- | --- |
| `AesUtils.py`、`RsaUtils.py` | 独立实现加解密（`tsn_crypto`） |
| `track_log.py` | 独立日志门面（`tsn_log`） |
| `track_geo.py` | 独立几何库（`tsn_geo`） |
| `step_buckets.py` | 独立分桶（`tsn_buckets`） |
| `track_clean.py`、`track_validate.py` | 独立清洗 / 自洽校验（`tsn_track_filter`、`tsn_track_audit`） |
| `tsn_environment.py`、`tsn_payload.py`、`tsn_face_schedule.py` | 独立设备报文、提交要素、人脸时机（`tsn_env`、`tsn_submit`、`tsn_face_plan`） |
| `services/`（含 3 个 `__init__.py` + 2 个 Dao） | 合并为单文件 `tsn_dao.py` |
| `README.upstream.md` | 不再需要 |

每个被删文件在 `D:\TSN\archive\` 留了归档副本，仅用于录制/复核行为基线。

## 新模块映射

| 新模块 | 旧模块 | 对外 API |
| --- | --- | --- |
| `tsn_crypto` | `AesUtils` + `RsaUtils` | `AESCrypto(key, iv, ecb_mode).encrypt/.decrypt/.decrypt_zero_padded`、`RSACrypto(pub).encrypt_bytes/.encrypt`、`pkcs7_pad/unpad`、`zero_pad/unpad` |
| `tsn_log` | `track_log` | `logger`、`get_logger(name)` |
| `tsn_geo` | `track_geo` | `haversine_distance`、`LocalProjection`、`normalize_points`、`point_list_distance`、`WGS84/GCJ02/BD09` |
| `tsn_buckets` | `step_buckets` | `StepInterval`、`BucketAllocation`、`allocate_steps`、`intervals_from_samples` |
| `tsn_track_filter` | `track_clean` | `CleanOptions`、`CleanResult`、`clean_track`、`InsufficientTrackError` |
| `tsn_track_audit` | `track_validate` | `validate_series`、`validate_track`、`ValidationReport`、`Issue` |
| `tsn_env` | `tsn_environment` | `EnvSignals`、`clean_device_signals`、`build_environment_payload`、`probe_device` |
| `tsn_submit` | `tsn_payload` | 签名要素、`aggregate_risk_flags`、`per_run_range_meters`、`required_steps`、`adaptive_end_qualified_time`、`is_valid_qualified`、`qualification_detail`、`build_submit_extras` |
| `tsn_face_plan` | `tsn_face_schedule` | `FacePoint`、`normalize_middle_faces`、`build_middle_face_points` |
| `tsn_dao` | `services/*` | `getTsnAccountByid/ByUid`、`updateAccessToken`、`addTsnAccount`、`getSchoolListDao`、`getSchoolBySchoolId`、`addOrUpdateSchool` |

## 怎么证明「重写没改行为」

重写前先跑 `tools/snapshot_legacy.py`，把九个纯函数模块的输出冻结成
`tests/fixtures/legacy_golden.json`（几何距离表、分桶、清洗、重采样 869 个点、校验指标、
提交要素、设备报文原字符串、人脸点、AES 三组向量）。重写后
`tests/test_legacy_equivalence.py` 逐项比对 —— **10 个用例全绿**。
归档副本仍在，`TSN_LEGACY_DIR` 可指定别的目录重录基线。

## 唯一一处故意不一致

`AesUtils.decrypt` 在「末字节是 0x00」时会把结果截成空串（`s[:-ord(s[-1:])]`）。
真实 App 用零填充加密，明文长度恰好是 16 的倍数时会**多补一整块** `0x00`，
旧实现解出来必然丢掉整段明文。新实现 `decrypt_zero_padded` 修正了这个缺陷，
`tests/test_legacy_equivalence.py` 里对这条专门断言「golden 是空串，新实现给出正确明文」。

# 第四轮（v5）：分档门禁

19 条「硬条件」里有 7 条会误杀真实合格记录（步幅、步频、60 s 桶上下限、点串链长上限、
整秒对齐、起跑时段、步数≥里程/1.2）。原因不是阈值设错，而是**把「像不像真人」当成了「服务器卡不卡」**。

现在每条检查带 tier：

| tier | 含义 | `balanced` 下致命？ |
| --- | --- | --- |
| `protocol` | 报文结构（9 键、全字符串、`t` 递增、配速格式）→ 服务器直接 403/999 | 是 |
| `server` | 有真实拒绝证据的硬闸门 | 是 |
| `heuristic` | 从 5 条合格记录归纳的区间 | 否，只提醒 |
| `self` | 我们自设的保守要求（设备画像） | 否，只提醒 |

验证方式：`tools/audit_gates.py` 回放 14 条真实记录 —— 5 条合格 0 误杀，
3 条被拒各自命中对应闸门（`step_setting_low` / `face_status` / `identify`+`pace_format`）。
